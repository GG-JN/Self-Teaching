## Why this repository exists

It's easy to get comfortable when you spend most of your time working with the same technologies.

I want to deliberately step outside that comfort zone.

This repository is where I keep track of the bigger projects I build to do that. Each project lives in its own repository; this one is mainly the index and the place where I document what I built, why I built it, what went wrong, and what I learned along the way.

The goal isn't to build perfect projects. The goal is to build things complicated enough that I have to make decisions I haven't had to make before.

## Goals

I want to build **two substantial projects every year**.

They shouldn't be toy apps or projects built just to try out a framework. They should be big enough to involve real architectural decisions, trade-offs, and things that can actually go wrong.

Every project should have, at minimum:

1. **Production-like architecture.** Persistence, authentication, testing, observability, CI/CD, deployment, and the other things that come with running a real application.
2. **An AI component.** AI should solve an actual problem in the project, rather than being added just because it looks good in a demo.
3. **Documentation.** I want to write down the important decisions I make, including the ones that turn out to be wrong.
4. **Something that runs.** Ideally a deployed version, otherwise a setup that someone else can reproduce and run easily.

The point isn't to collect GitHub stars.

If a project is finished and I can look back and say *"I wouldn't have known how to design this a year ago"*, then it was worth building.
